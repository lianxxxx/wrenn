Date: 2026-11-07. Sources were read on this date. Anthropic changes these pages often, so re-check before launch.

## 1. Is it allowed to run the user's own Claude Code?

### Answer

Partly, and it's grey. Anthropic's own docs say an end user may sign in to the **unmodified** Claude Code binary with their own subscription, even when someone else's product runs it. But the same page says developers building products "should use API key authentication" and may not "route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users." Wrenn sits between those two lines. The safe path is: the user's own API key. Running their subscription is possible, but not clearly approved.

### Details

**Clearly allowed**

- An end user signing in to the unmodified Claude Code binary with their own subscription, "including where a platform hosts Claude Code." (Legal and compliance page.)
- Saying in plain text that Wrenn "runs Claude Code". (Same page.)
- Using the user's own API key (Agent SDK or `claude -p`), billed to the user. Consumer Terms allow automated access "via an Anthropic API Key".

**Clearly not allowed**

- Offering a "Sign in with Claude" (claude.ai login) inside Wrenn itself. The Agent SDK page says: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK."
- Collecting, storing, or passing along the user's Claude.ai credentials or session tokens (for example reading `.credentials.json`, or asking the user to paste a `claude setup-token` token into Wrenn). Sign-in "must complete through Anthropic's own flow."
- Modifying Claude Code, or removing any of its sign-in methods.
- Paying for, reselling, or sitting in the middle of the user's Claude usage.
- Using "Claude Code" in Wrenn's product name or logo, or making it look like an Anthropic product.

**Grey (unclear)**

- Wrenn launching the user's already installed, already signed-in `claude` in the background with `claude -p`. Arguments for "ok": the binary is unmodified, the user signed in through Anthropic's flow, Wrenn never touches the token, and usage is billed to the user. Arguments against: the Consumer Terms ban automated access "through a bot, script, or otherwise" except with an API key "or where we otherwise explicitly permit it", and the docs say product developers should use API keys. The docs also say plan limits "assume ordinary, individual usage of Claude Code and the Agent SDK."
- Anthropic's help center (update of June 15, 2026) says "Agent SDK, `claude -p`, and third-party app usage" still draw from subscription limits. That reads like third-party app use on a subscription is a known, tolerated thing, but it's not a written permission.
- The "Can customers offer Claude Code in their products?" section says running Claude Code in your product requires agreeing to the Commercial Terms. It's unclear if that applies to a free desktop app that only launches a copy the user installed themselves.
- In February 2026 Anthropic blocked subscription OAuth in third-party apps that used the token directly (secondary reports). That was about apps reusing the token, not about launching the real CLI, but it shows they do enforce, "without prior notice".

**Fallback: user's own API key**

- The user makes a key at platform.claude.com, pastes it into Wrenn's setup screen, and Wrenn passes it as `ANTHROPIC_API_KEY` to `claude -p` (or to the Agent SDK). In `-p` mode an `ANTHROPIC_API_KEY` in the environment is always used and outranks the subscription login.
- Cost per video, rough estimate (my numbers, not Anthropic's): a small job writing 4 to 6 HTML/GSAP scenes is about 10 to 15 agent turns, roughly 60k tokens written to cache, 400k cache reads, 10k fresh input, 20k to 30k output.
  - Claude Sonnet 5.5 ($2 in, $2.50 cache write, $0.10 cache read, $10 out per million tokens): about **$0.15 + $0.04 + $0.02 + $0.25, so roughly $0.50 per video** (range $0.30 to $1).
  - Claude Opus 5.5 ($4 / $5 / $0.20 / $20): about **$1 per video** (range $0.60 to $2).
  - Claude Haiku 5.5 ($0.10 / $0.125 / $0.01 / $0.50, prompts up to 100k): a few cents.
  - Retries and fix-up turns can double these. `claude -p --output-format json` reports `total_cost_usd`, and `--max-budget-usd` can cap a run.
- Max, Ultra and Team plans now include monthly API credits that cover the Agent SDK and `claude -p` when run with an API key from the user's linked Console org (help center, October 7, 2026). So some subscribers could use the API key path at no extra cost. Amounts per plan: unclear (not on the page I read).

## 2. HyperFrames

### Answer

HyperFrames is HeyGen's open-source HTML to video framework, Apache 2.0 (works fine with Wrenn's MIT license, keep their NOTICE/credit). It renders by seeking paused GSAP timelines frame by frame in headless Chrome (Puppeteer) and encoding with FFmpeg. It runs on Windows. It's popular (about 80k GitHub stars) but still pre-1.0 (v0.9.19) and changes several times a day.

### Details

- **License:** Apache-2.0 (LICENSE file and GitHub API). Commercial use allowed. Media you add keeps its own license.
- **Maturity:** created March 2026, latest tag v0.9.19 (Nov 6, 2026), three releases in one day. Expect breaking changes.
- **How it renders:** frame time is `floor(frame) / fps`, every animation is seeked (GSAP timelines are paused and registered on `window.__timelines`), Chrome's `HeadlessExperimental.beginFrame` grabs each frame, FFmpeg encodes and mixes audio from `<audio>`/`<video>`. If BeginFrame fails, it falls back to screenshot capture (v0.9.8 release notes). This is the same idea as Wrenn's "every scene supports `seek(time)`" rule.
- **Needs a headless browser:** yes. The engine launches `chrome-headless-shell` via Puppeteer; the CLI downloads it with `@puppeteer/browsers`. It does not use Electron's Chromium.
- **Needs FFmpeg:** yes ("Rendering needs FFmpeg"). It looks for `HYPERFRAMES_FFMPEG_PATH`, else PATH. So Wrenn could point it at `ffmpeg-static`'s binary.
- **Node:** 22 or later.
- **Windows:** FAQ says "The CLI and the agent skills run on Windows, including rendering from PowerShell." Byte-identical output across machines needs their Docker mode, which Wrenn's users won't have. Normal local renders can differ by a pixel between machines.
- **Embedding:** `@hyperframes/producer` has `createRenderJob()` and `executeRenderJob(job, projectDir, outPath, onProgress)` with cancel via `AbortSignal`. Outputs MP4 (AAC), WebM, MOV, GIF, PNG sequence.
- **Agent skills:** `npx skills add heygen-com/hyperframes` ships skills for Claude Code, which could help Claude write valid scenes.

**Fit for Wrenn**

| Option | Good | Bad |
| - | - | - |
| HyperFrames | Seek-based, audio mux, progress callback, skills for Claude, Apache 2.0 | Downloads its own Chrome (~100+ MB) on top of Electron's, needs Node 22 and FFmpeg setup, pre-1.0 churn |
| Playwright capture | Well known, Wrenn already plans Playwright for tests | Also needs its own browser download, Wrenn writes the seek/capture/encode loop itself |
| Electron's own Chromium (offscreen `BrowserWindow` + `capturePage` or `webContents` paint) | No extra browser, smallest install, full control | Wrenn writes the frame loop itself, no BeginFrame so must wait for paint after each seek |

My read: for v1, Electron's own Chromium keeps the installer small and avoids a second browser. HyperFrames is a strong option if the team would rather not write the capture loop, or as a reference for how to do seeking and audio mixing well. Keep Wrenn's scene format close to HyperFrames' (paused GSAP timeline per scene) so switching later stays cheap.

## 3. Detecting and running Claude Code on Windows

### Answer

Run `where claude` (or try the known paths), then `claude --version`, then `claude auth status`, which prints JSON and exits 0 if signed in, 1 if not. Run jobs with `claude -p "<prompt>" --output-format stream-json --verbose` from Node's `spawn` with `cwd` set to the job folder, and lock it down with `--tools` and `--permission-mode acceptEdits`.

### Details

**Is it installed?**

- Native installer (recommended by Anthropic): `%USERPROFILE%\.local\bin\claude.exe` (from the official uninstall steps).
- npm global: `npm install -g @anthropic-ai/claude-code`. On Windows npm puts a `claude.cmd` shim in npm's global folder, by default `%APPDATA%\npm` (npm folders docs).
- WinGet: `winget install Anthropic.ClaudeCode`. Install folder: unclear, rely on PATH.
- Easiest check: run `where claude` and take the first result, then fall back to the native path above. Note: an Electron app started from the Start menu keeps the PATH it had when it launched, so if the user installs Claude Code while Wrenn is open, Wrenn may not see it until restart. Checking `%USERPROFILE%\.local\bin\claude.exe` directly avoids that (general Windows behaviour, not from Anthropic docs).
- Spawning a `.cmd` file from Node needs `shell: true` on Windows since Node's April 2024 security fix; `claude.exe` does not.
- `claude doctor` gives read-only install diagnostics if something looks wrong.

**Version**

- `claude --version` prints e.g. `2.1.211 (Claude Code)`. Parse the first number. Some flags need newer versions (for example `--permission-prompts` needs 2.1.259+, `--restricted` needs 2.1.248+), so set a minimum.

**Signed in?**

- `claude auth status`: "Show authentication status as JSON... Exits with code 0 if logged in, 1 if not." The `authMethod` field is one of `none`, `claude.ai`, `oauth_token`, `api_key`, `api_key_helper`, `third_party`. This is the cleanest check, no tokens spent.
- Credentials file on Windows: `%USERPROFILE%\.claude\.credentials.json` (or under `CLAUDE_CONFIG_DIR` if set). Wrenn may check that it exists, but must not read or copy its contents (see Q1).
- If the login is missing or expired, `claude -p` prints the failure as the result on stdout, and stream-json emits `system/api_retry` events with `error: "authentication_failed"`. Wrenn can't log the user in itself (`/login` isn't available in `-p`), so show a "Open a terminal and run `claude`" step.
- Free claude.ai plans don't include Claude Code; Pro, Max, Ultra, Team, Enterprise, or Console are needed.

**Running headless with progress**

```
claude -p "<prompt>" --output-format stream-json --verbose
```

- Spawn with `cwd` set to the job folder, e.g. `%APPDATA%\Wrenn\jobs\<id>\`. That folder is Claude's working directory.
- Each stdout line is one JSON event. The first is `system/init` (model, tools). The last is `result` with final text, `total_cost_usd`, and `session_id`. Add `--include-partial-messages` for token-by-token text. Map `tool_use` events (Write/Edit of `scene-1.html` etc.) to a progress bar.
- Exit code 0 means success, non-zero means failure.
- Cancel with SIGINT (ends the turn cleanly), not SIGTERM (exit 143, turn left unfinished).
- `--max-turns` and `--max-budget-usd` put a ceiling on runaway jobs.
- Pass the long prompt via stdin instead of the command line (stdin cap is 10MB) to avoid Windows command-length limits.

**Keeping it inside one folder**

- `--tools "Read,Write,Edit,Glob,Grep"` removes Bash/PowerShell and web tools entirely, so Claude can only touch files.
- `--permission-mode acceptEdits` auto-approves edits only inside the working directory (and `--add-dir` folders). Writes outside are not auto-approved, and since `-p` runs (v2.1.302+) start in Manual mode, anything needing approval is denied.
- `--restricted` (v2.1.248+) removes command tools, confines file tools to the working directories, refuses `bypassPermissions`, and skips the user's own settings. Good fit for Wrenn.
- `--disallowedTools "mcp__*"` blocks any MCP tools from the user's own setup.
- Consider `--permission-prompts none` so nothing waits on a prompt nobody will answer.
- `--bare` skips the user's hooks, CLAUDE.md, plugins and MCP servers (good, predictable), **but bare mode never reads the subscription login**, only `ANTHROPIC_API_KEY`. So: use `--bare` on the API key path; on the subscription path use `--restricted` instead.
- Never use `--dangerously-skip-permissions`.
- Copy the user's uploaded assets into the job folder first, so Claude doesn't need `--add-dir`.

Example (subscription path):

```
claude -p --restricted --tools "Read,Write,Edit,Glob,Grep" --disallowedTools "mcp__*" --permission-mode acceptEdits --permission-prompts none --output-format stream-json --verbose --max-turns 30
```

Example (API key path): same, plus `--bare`, with `ANTHROPIC_API_KEY` set only in the child process env.

## Recommendation for Wrenn

- Offer **two modes on the setup screen**: "Use my Claude Code sign-in" and "Use my Anthropic API key". Make the API key path the documented, safe one, and label the subscription path honestly as using the user's own plan limits.
- Before shipping the subscription mode, **email Anthropic** (the legal page links to sales for "questions about permitted authentication methods") describing exactly what Wrenn does, and keep the answer in the repo.
- Never read, copy or ask for Claude tokens. Only call `claude auth status` and spawn the real `claude` binary. Don't call the feature "Claude Code" in Wrenn's own UI names; "Runs your Claude Code" in plain text is fine.
- Run jobs locked down: job folder as `cwd`, `--restricted`, file-only `--tools`, `acceptEdits`, `stream-json` for progress, `--max-turns` and (API key) `--max-budget-usd`.
- For v1 rendering, use **Electron's own Chromium** with a seek-based loop and `ffmpeg-static`. Shape scenes like HyperFrames (one paused GSAP timeline per scene) so moving to HyperFrames later is easy if the hand-rolled loop gets painful.

## Still unclear

- Whether launching the user's own signed-in `claude -p` from a free, open-source app counts as "ordinary, individual usage" or as routing subscription credentials "on behalf of their users". Only Anthropic can answer this.
- Whether the "Can customers offer Claude Code in their products?" Commercial Terms requirement covers a desktop app that does not ship or install Claude Code itself.
- Monthly API credit amounts per plan (Max, Ultra, Team), and whether Pro gets any.
- WinGet's install folder for `claude.exe`.
- HyperFrames: whether BeginFrame works on Windows Chrome or it always uses the screenshot fallback there, and how big its Chrome download is on Windows.
- The per-video cost is my estimate. Measure it with `total_cost_usd` on a real template before putting numbers in the app.
