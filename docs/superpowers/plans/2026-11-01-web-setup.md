# Web Setup + Shared Tokens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working Next.js project in `web/` that loads Wrenn's shared tokens and local fonts, with a brand test page and one Playwright smoke test.

**Architecture:** `brand/tokens.css` holds every token from `DESIGN.md` as a Tailwind v4 `@theme` block (shared by web now, desktop later). `web/src/app/globals.css` imports Tailwind, then the shared tokens. Fonts are loaded with `next/font/local` from copies in `web/src/fonts/`, exposed as CSS variables that the font tokens point to.

**Tech Stack:** Next.js (latest, App Router), TypeScript, Tailwind CSS v4, `@playwright/test`.

**Spec:** `docs/superpowers/specs/2026-11-01-web-setup-design.md`

## Global Constraints

- No Google Fonts CDN. Fonts come from local files only.
- Only new dependency beyond the Next.js scaffold: `@playwright/test` (dev).
- Do not touch `desktop/`.
- Background token `--color-bg` defaults to cream `#FFF8EC`.
- Token values copied exactly from the `DESIGN.md` frontmatter.
- No em dashes in any copy.

## Review Focus

- **Vercel build with root directory `web/`:** the import of `../../../brand/tokens.css` reaches outside `web/`. Vercel includes files outside the root by default, but if that setting is off the build fails. Expect: note it in `web/README.md`.
- **Font fallback:** if a font file fails to load, text must fall back to `system-ui`, not a serif. Pinned by the font-family assertion in Task 2.
- **Token import order:** tokens must come after `@import "tailwindcss"` or Tailwind defaults win. Pinned by the color assertions in Task 2.
- **Windows paths:** all imports use forward slashes.
- **Dark background blob rule:** only red and teal blobs with white text on navy. Shown on the test page, checked by eye.
